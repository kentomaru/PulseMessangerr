# ⚡ Pulse — мессенджер

Мессенджер на Next.js 15: личные чаты, **группы и каналы с ролями**,
**групповые голосовые/видеозвонки (WebRTC mesh) со ссылкой-приглашением**,
**истории (24 ч)**, **обои чатов**, настройки **приватности**, ответы на
сообщения, фото-сообщения, индикатор «печатает…», галочки прочтения,
онлайн-статусы.

## Возможности

| Функция | Как работает |
| --- | --- |
| 💬 Чаты | личные диалоги, поиск людей по @имени, непрочитанные, «печатает…», ✓/✓✓ прочтение, удаление сообщений |
| ↩️ Ответы | кнопка «Ответить» у сообщения → цитата в пузыре, клик по цитате перематывает к оригиналу; если оригинал удалён, цитата показывает «Сообщение удалено» |
| 👥 Группы | создание с участниками, аватар, название, описание, роли **владелец / админ / участник**, добавление и исключение людей, выход (владение переходит следующему), удаление группы владельцем |
| 📢 Каналы | то же, что группы, но писать могут только администраторы; у подписчиков поле ввода закрыто |
| 🔎 Обзор | публичные группы и каналы ищутся в «Обзоре» (кнопка в сайдбаре) — с числом участников и кнопкой «Присоединиться»; приватные там не видны |
| 🔗 Ссылки-приглашения | у группы/канала постоянная ссылка `…/#group=<token>` — по ней входят даже в приватные |
| 📞 Звонки | аудио и видео через WebRTC: трафик идёт **напрямую между браузерами** (mesh: каждый участник соединён с каждым), сервер — только сигнальный центр (SDP/ICE в БД). В ЛС — дозвон («Звонит…» → принял/отклонил/пропущен), в группе/канале — комната, к которой можно присоединиться в любой момент. Лог звонка падает в чат: «Звонок · 2:31», «Пропущенный», «Отменённый» |
| 🌍 Звонок «откуда угодно» | в окне звонка кнопка «скопировать ссылку» → `…/#join=<token>`. Ссылку можно кинуть кому угодно: человек откроет её, увидит превью («Разработчики · 3 в звонке») и войдёт — даже если он не участник чата (в ЛС он останется гостем звонка, переписку не увидит; в публичной группе заодно станет участником). Второе средство — кнопка «+» в звонке: поиск по @имени и приглашение в текущий звонок |
| 🫧 «Динамический остров» | звонок сворачивается в перетаскиваемую пилюлю в углу: таймер, число участников, микрофон, «развернуть», «выйти». Чат, сайдбар и истории остаются доступны, звук продолжает идти |
| 📸 Истории | кружок «+» в сайдбаре → фото + подпись, живут 24 часа. В просмотре видно, **кто выложил** (клик по имени — карточка профиля), а автор видит список посмотревших; свои можно удалить |
| 🎨 Обои чатов | меню в шапке чата → 10 пресетов или своя картинка; у каждого участника свои |
| 🔒 Приватность | группа/канал — приватные (только по приглашению) или публичные (видны в «Обзоре»); у профиля: скрыть «в сети», запретить звонки, запретить новые чаты, выход со всех устройств, полное удаление аккаунта, страница `/privacy` |
| 🩺 Надёжность | retry-подключение к БД, healthcheck `/api/health`, подробные логи, идемпотентный перенос схемы при старте |

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env          # укажите DATABASE_URL
npm run dev                   # http://localhost:3000
```

Нужен PostgreSQL (14+). Таблицы создаются автоматически при старте сервера
(`ensureSchema` — идемпотентный DDL), отдельный шаг миграций не требуется:
старая схема звонков 1:1 переносится на комнаты один раз, старым группам
проставляется `kind` и владелец. Для ручной работы со схемой:
`npm run db:push` (drizzle-kit).

Переменные окружения:

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `DATABASE_URL` | да | строка подключения PostgreSQL, например `postgres://user:pass@host:5432/pulse` |
| `LOG_LEVEL` | нет | `debug` \| `info` (по умолчанию) \| `warn` \| `error` |
| `APP_URL` | нет | публичный адрес приложения — подставляется в ссылки-приглашения (`https://pulse.up.railway.app`). Без него ссылки собираются от текущего origin |
| `NEXT_PUBLIC_TURN_URL` | нет | TURN-сервер для звонков за строгим NAT, например `turn:turn.example.com:3478` (можно несколько через запятую) |
| `NEXT_PUBLIC_TURN_USERNAME` | нет | логин TURN |
| `NEXT_PUBLIC_TURN_CREDENTIAL` | нет | пароль TURN |

## Деплой на Railway

1. Создайте проект → **New → Database → PostgreSQL**.
2. Добавьте сервис из GitHub-репозитория.
3. В Variables сервиса приложения добавьте `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   (Railway подставит приватную ссылку сам, если добавить Postgres в тот же проект).
4. Туда же полезно добавить `APP_URL` = публичный домен сервиса — тогда
   скопированные ссылки-приглашения сразу открываются у других людей.
5. Готово. `railway.json` уже настроен:
   - start: `npm run start`;
   - healthcheck: `/api/health` (щедрый таймаут 300 с);
   - при падении — до 10 автоперезапусков.

### Почему сервер больше не падает, если база стартует позже приложения

Раньше код обращался к БД на этапе запуска, и если Postgres ещё не поднялся,
процесс падал. Теперь:

- при старте `src/instrumentation.ts` ждёт базу: **попытка → 2 секунды → новая попытка**;
- первые ~16 секунд — в блокирующем режиме (обычно база готова за 2–4 с);
- если база всё ещё поднимается — сервер **продолжает работать**, ждёт в фоне,
  страница показывает экран «Подключаемся к базе данных» (сам обновится),
  API отвечают `503` и **повторяют запрос через 2 секунды** автоматически;
- когда база отвечает — схема создаётся/дополняется автоматически, всё
  начинает работать без перезапуска;
- healthcheck честно возвращает `200` только когда база жива.

Дополнительно: Next.js собирает `instrumentation.ts` и для edge-слоя, где
нет Node-модулей (`net`, `tls`), нужных драйверу `postgres`. В `next.config.ts`
драйвер и Node-модули помечены внешними для edge-целей — без этого любой
запрос в `next dev` падал с `Module not found: Can't resolve 'net'`.

### Ошибка сборки «Cannot find native binding»

Симптом: деплой на Railway падает на `npm run build` с ошибкой вида

```
Error: Cannot find module '../lightningcss.linux-x64-gnu.node'
Cannot find native binding
```

Причина: Tailwind v4 и его CSS-движок (`@tailwindcss/oxide`, `lightningcss`)
подтягивают платформенные бинарники через **optional dependencies**. В окружении
сборки Railway они могут не установиться (npm пропускает optional-пакеты при
ошибке сети/платформы), и postcss падает уже на `src/app/globals.css`.

Фикс (уже применён):

- в `package.json` linux-бинарники закреплены явно:

  ```json
  "optionalDependencies": {
    "@tailwindcss/oxide-linux-x64-gnu": "4.3.3",
    "@tailwindcss/oxide-linux-arm64-gnu": "4.3.3",
    "lightningcss-linux-x64-gnu": "1.32.0",
    "lightningcss-linux-arm64-gnu": "1.32.0"
  }
  ```

- в `railway.json` сборка идёт командой, которая не даёт их пропустить:

  ```json
  "buildCommand": "npm ci --include=optional && npm run build"
  ```

Проверить локально: `rm -rf node_modules/lightningcss-linux-x64-gnu
node_modules/@tailwindcss/oxide-linux-x64-gnu && npm run build` — до фикса
сборка падала, после `npm ci --include=optional` проходит.

## Логи: «где что сломалось?»

Все логи — структурированные, в stdout (Railway их показывает в Deploy Logs):

```
[2026-09-11T13:40:22.290Z] [INFO] [api:messages] POST /api/messages → 200 ms=7
[2026-09-11T13:40:22.290Z] [INFO] [calls] Участник вошёл в звонок callId=… userId=… participants=3 guest=false
[2026-09-11T13:40:22.290Z] [WARN] [db] База данных недоступна (попытка 3/45). Повтор через 2 с err=ECONNREFUSED
[2026-09-11T13:42:38.196Z] [ERROR] [api:conversations] GET /api/conversations: необработанная ошибка err={...stack...}
```

- `[api:...]` — каждый HTTP-запрос: метод, путь, статус, длительность;
- `[calls]` — жизненный цикл звонков: кто вошёл/вышел, почему звонок завершился;
- `[db]` / `[startup]` — подключение базы и старт сервера;
- `[server]` — все неперехваченные ошибки Next.js (`onRequestError`);
- в логи **не** пишутся пароли, содержимое сообщений и SDP-описания звонков.

Поиск проблемы: `Ошибка` / `ERROR` → scope в квадратных скобках показывает,
какой роут/модуль упал, `ms=` помогает найти медленные запросы.

```
src/
├── app/
│   ├── page.tsx              — вход/мессенджер (SSR)
│   ├── privacy/page.tsx      — политика конфиденциальности
│   └── api/
│       ├── auth/*            — регистрация, вход, профиль, logout-all, удаление аккаунта
│       ├── users/*           — поиск людей, карточка пользователя
│       ├── conversations/*   — список/создание чатов, групп и каналов, настройки,
│       │                       участники и роли, ссылки-приглашения, join,
│       │                       прочтение, typing, обои
│       ├── discover          — «Обзор»: публичные группы и каналы
│       ├── messages/*        — отправка/получение/удаление сообщений, ответы
│       ├── calls/*           — комнаты: start, incoming, [id] (join|signal|state|
│       │                       invite|leave|end|decline), [id]/invite (ссылка),
│       │                       info/[token] (превью), join/[token] (вход «с улицы»)
│       ├── stories/*         — истории: лента, публикация, просмотры, удаление
│       ├── upload + files    — загрузка/раздача изображений
│       └── health            — healthcheck для Railway
├── components/               — UI: Sidebar, ChatView, CallStage (окно звонка +
│                               «динамический остров»), GroupCreateModal,
│                               GroupInfoModal, DiscoverModal, PeoplePicker,
│                               Stories*, Profile, UserCard, Wallpaper
├── lib/
│   ├── useCallController.ts  — клиентская логика mesh-звонков (WebRTC + опрос комнаты)
│   ├── calls.ts              — серверная часть звонков: комнаты, участники, сигналы, логи
│   ├── conversations.ts      — роли/доступы, сериализация чатов, ссылки-приглашения
│   ├── api-helpers.ts        — withApi: авторизация + логи + retry БД + единые ошибки
│   └── logger.ts             — структурированный логгер
├── db/                       — drizzle-схема + подключение с retry + ensureSchema
└── instrumentation.ts        — стартовый hook: ожидание БД + ensureSchema + onRequestError
```

Реальное время — короткий опрос (1.2–4 с): чаты каждые 4 с, сообщения 2.5 с,
входящий звонок 3 с, состояние активного звонка 1.2 с (этот же запрос —
heartbeat: если участник молчит 90 с, сервер считает его выбывшим). Для
небольшого числа пользователей этого достаточно, а WebSocket-сервер не требуется.

### Как устроены звонки

- **Комната на диалог**: `calls` (статус `ringing`/`live`/`ended`/`missed`/`declined`,
  `join_token`), `call_participants` (кто в комнате, SDP, флаги микрофона/камеры,
  гость ли), `call_signals` (offer/answer/ice очередью адресату), `call_invites`
  (кого позвали — он увидит звонок во входящих).
- **ЛС**: звонок `ringing`, становится `live` когда второй принял, завершается
  как только кто-то вышел. **Группа/канал**: комната `live` сразу, живёт пока
  в ней есть люди; опоздавшие видят в шапке чата «В звонке · N» и входят.
- **Соединение**: mesh, у каждого участника по `RTCPeerConnection` с каждым.
  Оффер шлёт детерминированно «меньший» по id — встречные офферы (glare)
  разруливаются откатом, как в perfect negotiation. Если ответ потерялся,
  оффер переотправляется через 6 с.
- **Кто может войти**: участник диалога → приглашённый (`call_invites`) →
  любой по `join_token` (гость). В приватном ЛС гость видит только звонок.

## Звонки и группы: как проверить

Откройте мессенджер в двух окнах (обычное + инкогнито) под разными аккаунтами:

1. **ЛС-звонок**: создайте чат, нажмите 📞 или 📹 → во втором окне появится
   входящий. Разрешите доступ к микрофону/камере.
2. **Группа**: «+» в сайдбаре → «Создать группу» (или канал), добавьте людей,
   в карточке группы (клик по шапке) — роли, ссылка-приглашение, приватность.
3. **Групповой звонок**: в группе нажмите 📞 — комната живая сразу; второй
   участник видит её во входящих и в шапке чата («В звонке · 1»).
4. **Ссылка «откуда угодно»**: в окне звонка — кнопка «скопировать ссылку»,
   откройте её в третьем окне под другим аккаунтом (или отправьте любому
   человеку): появится превью и вход в звонок.
5. **«Динамический остров»**: кнопка «свернуть» в окне звонка — пилюлю можно
   перетащить, звук и чат продолжают работать.
6. **Ответы**: наведите на сообщение → «Ответить»; клик по цитате — переход к
   оригиналу.
7. **Истории**: «+» в сайдбаре → публикация; в просмотре кликните по имени
   автора — откроется его карточка.

Звонок соединяется напрямую (P2P). Используется публичный STUN; если сеть
блокирует P2P (симметричный NAT), задайте свой TURN через
`NEXT_PUBLIC_TURN_URL` / `NEXT_PUBLIC_TURN_USERNAME` / `NEXT_PUBLIC_TURN_CREDENTIAL`.

## Заметки

- Загруженные файлы хранятся в `data/uploads` (на Railway диск ephemeral —
  при пересоздании контейнера картинки пропадут; для постоянного хранения
  подключите S3-совместимое хранилище и замените `/api/upload`).
- Пароли — scrypt-хэш, сессии — httpOnly-cookie на 30 дней.
- Mesh-звонки — это N·(N−1)/2 соединений: для 4–6 человек комфортно, для
  больших собраний нужен SFU (LiveKit/mediasoup).
